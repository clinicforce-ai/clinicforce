The existing backend suite tests the broader eCW/Stedi/FastAPI route, saved cases and historical office benefits. The normal full backend run passed 1,622 tests with 87 skipped before the final date-migration assertion; frontend rendering passed 15 assertions and format, lint, build/type and source size passed. The [69-case counterfactual](../../../contextforcodex/collection-engine-october-replay-2026-11-02.md) ran against saved original normalized evidence and current scoped rates. The expanded staging seed returned 38 fake cases and 76 saved iterations; all 38 FastAPI reads matched their declared final decisions. The later Phase 7/9 focused suite passed 49 tests against disposable PostgreSQL, including read-only upcoming-visit checks and idempotent migration of the new fake cases. The marked saved-read path uses synthetic prices and policies from the case and makes no eCW, Stedi or Bedrock call; it does not validate live Library refresh. Synthetic approvals apply only to fake patient/payer/product IDs and cannot be treated as real NMCT authority. Exact historical config reconstruction and real NMCT visit-policy approval remain open.
